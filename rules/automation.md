# 求职辅助：BOSS 自动沟通与智联自动投递（浏览器原型 + Android）

## 功能范围

- 入口：“我的”页净资产卡下方的求职辅助卡（浏览器 `job-entry-card`，Android `JobEntryCard`），显示状态（空闲 / 自动沟通中 / 自动发简历中 / 已暂停 / 已停止）与今日沟通、简历、待回复计数；任务运行或暂停时，详情页以外的页面在底部导航上方显示全局状态条（`job-run-bar` / `JobRunBar`），可点回详情或暂停/继续；空闲时不显示。两端共用 `autoApplyEntry` / `AutoApplyRules.entry`。详情页从上到下：状态卡（空闲 / 运行中 / 已暂停 / 最近停止原因，今日沟通、今日简历、待回复三个计数，运行中显示暂停/继续与停止）→ 准备清单（编号 1–4，带对应操作按钮，全部完成后折叠为“✓ 准备就绪”）→ 分段切换「沟通 / 简历 / 进度 / 数据」→ 默认折叠的“高级 · 界面诊断”。按钮不可用时须在下方用小字写明原因，不只是置灰。
- 用户已确认：无人值守批量投递、没有官方接口时仍通过无障碍服务操作 App。平台只有 BOSS 直聘和智联招聘，其他招聘平台不在范围内。
- 平台切换（`JobPlatform` / `JOB_PLATFORMS`）：状态卡顶部「BOSS 直聘 / 智联招聘」，每次运行只操作一个平台，运行中不能切换。今日计数、每日上限（BOSS `dailyLimit`、智联 `zhaopinDailyLimit`）、去重、「同公司每天一次」与试运行版本（`calibratedVersion` / `zhaopinCalibratedVersion`）按平台分开；筛选方案、关键词、黑名单、步进间隔、「我的简历」两个平台共用。记录带 `platform`，旧记录缺省为 BOSS。进度看板与数据复盘合并显示并标注来源平台。

## 自动投递硬边界（不得放宽，两个平台相同）

- 只操作用户本人手机上、本人已登录的 BOSS 直聘或智联招聘。无障碍服务须用户在系统设置中手动开启；`packageNames` 只限 `com.hpbr.bosszhipin,com.zhaopin.social`（智联包名待真机诊断核对），运行中只处理当前平台包名的事件。下文写「BOSS」的暂停、停止、亮屏、隐私规则同样适用于智联。
- **不规避平台风控**：不识别、不破解、不代填验证码；不伪装设备；不用随机延时或“模拟真人”手势躲检测（`canPerformGestures=false`，只用 `ACTION_CLICK` / `ACTION_SET_TEXT` / 返回键 / 滚动）。步进为事件驱动：BOSS 窗口状态或内容变化后防抖 350 ms 再读界面，两步之间至少间隔用户设定的固定秒数（默认 1 秒，1–30 秒，不随机）；另有 1 秒兜底轮询，用于超时与离开检测。
- 遇到验证页、登录页、BOSS 次数上限提示、无法识别的界面（超时 20 秒）、找不到要点的元素，立即停止并通知，不重试、不盲点。
- **暂停**（可从悬浮按钮或通知继续）：用户触碰 BOSS 界面、离开 BOSS（继续时用 launch intent 切回）、熄屏。暂停期间不执行任何步骤。继续时走纯函数 `AutoApplyEngine.resume` / `ResumeEngine.resume`：扫描阶段原地继续；处于职位或会话中间则回列表重扫；发简历在确认/发送阶段被暂停的公司本次不再处理，并提示到 BOSS 核对，避免重复发送。
- **停止**：上一条的验证、登录、上限、超时、找不到元素，以及悬浮按钮或通知点“停止”、关闭无障碍服务。
- 悬浮按钮由无障碍服务以 `TYPE_ACCESSIBILITY_OVERLAY` 添加（不申请悬浮窗权限），带 `FLAG_KEEP_SCREEN_ON`，运行中保持亮屏；不申请 WakeLock。熄屏后无障碍读不到界面，所以“后台运行”只承诺本应用可退到后台、手机亮屏放着，不承诺熄屏执行。
- 界面快照跳过 `isVisibleToUser=false` 的子树，避免点到屏幕外节点；路径仍按原始 child 下标记录。
- 不联网：`INTERNET` 保持 `tools:node="remove"`；不读取、不保存 BOSS 账号、Cookie、聊天内容。
- 每日上限默认 30，硬上限 100。同一职位（公司+岗位+薪资）只沟通一次；同一公司每天只联系一次；失败记录不阻止重试。
- 首次使用必须勾选风险确认（可能违反 BOSS 用户协议、账号可能受限，由用户承担）。真实执行前必须在当前 BOSS 版本上试运行成功（`calibratedVersion` 与已安装版本一致）；BOSS 更新后需重新试运行。
- 诊断导出只含 viewId、类名、文字长度、是否像薪资、固定按钮文字命中，不含职位、公司、聊天正文。
- “自动化已发起沟通”只代表服务看到了聊天页，不表述为 HR 已读或投递成功。

## 自动发简历（对方回复后）

- BOSS 只允许对方回复后发附件简历。用户已确认：HR 回复任何消息就发；按岗位类型预设简历名称，按名称选择附件。
- 触发条件只看「消息」列表的未读角标（viewId 含 unread/badge 等），且公司须对应本应用自动沟通过、尚未发简历的记录（`awaitingResume`）。**不读取聊天气泡和最后一条消息预览**，聊天页只读顶部职位卡片的岗位名用于核对。
- 「我的简历」在 App 内管理：`ResumeProfile(id, name, keywords, isDefault)`，最多 10 份、名称（去扩展名、忽略大小写）不重复、最多一份默认；非默认简历必须有关键词。按列表顺序取第一份关键词命中的简历，都没命中用默认简历，没有默认则跳过并记日志。列表可上移调整优先级。0.9.9 的 `resumeRules` 读取时转换为不设默认的简历（id `legacy-N`）。
- 消息列表的公司与沟通记录严格匹配（去掉空白和括号内容后相等，`sameCompany`），避免「华为」误配「华为云计算」；岗位仍用包含匹配。
- 简历名称整名比较（忽略大小写和扩展名）。选择列表里找不到同名附件、或确认框里核对不到同名附件，立即停止且不发送。
- 每个职位只发一次（`RESUME_SENT` 记录），每日上限与沟通分开计数。真实执行前须在当前 BOSS 版本做发简历试运行（`resumeCalibratedVersion`）。验证、登录、上限、超时、找不到元素的停止规则与沟通流程相同。
- 草稿状态“自动化已发送简历”只代表界面上点了发送，不代表 HR 已查看。

## 智联自动投递

- 用户已确认：智联只做自动投递，不做回复后发简历，不读消息页。流程（`ZhaopinApplyEngine`）：职位列表 → 按同一套规则决定 → 打开详情 → 点「申请职位 / 投递简历 / 立即申请」→ 弹出简历选择时按「我的简历」规则（关键词命中，否则默认）整名核对后选择 → 确认 → 看到「投递成功」提示或按钮变为「已申请」→ 返回列表。
- 没弹简历选择时按智联默认简历投递，记录备注「智联默认简历」。弹出选择但没有可用简历或核对不到同名简历：立即停止，不投递。详情页已是「已申请 / 已投递」记为 `ALREADY_CONTACTED` 并返回。
- 暂停后继续：扫描阶段原地继续；点过投递后被暂停的职位本次不再处理（已在本轮 seen 中），并提示到智联核对，宁可漏投也不重复投。
- 记录结果 `APPLIED`（浏览器 `applied`），只代表界面上点了投递并看到成功或「已申请」，不代表 HR 已查看。进度看板建档为 `AUTO_APPLIED`（「自动化已投递（智联）」），阶段与已发简历相同；之后的 BOSS 沟通记录不会把它退回已沟通。
- 识别（`ZhaopinScreenReader`）与 BOSS 同样只靠文字和 viewId 片段猜测，职位卡片沿用 `BossScreenReader.parseCard`；必须用真机诊断导出核对。真实投递前须在当前智联版本试运行成功。

## 筛选方案

- 方案只保存岗位关键词、排除词、最低月薪、城市、招呼语（`AUTO_PRESET_FIELDS` / `FilterPreset`）；公司黑名单、每日上限、步进间隔、简历是全局设置，不随方案切换。最多 10 套，名称 1–20 字，忽略大小写不重名，同名保存即覆盖（保留原名）。
- 切换方案 = 把方案字段写回设置顶层（`applyAutoApplyPreset` / `AutoApplyRules.applyPreset`），引擎只读顶层，不改状态机。运行中不能切换。有当前方案时，在「沟通规则」里保存会同步更新该方案。删除方案不改当前规则。
- 新的沟通记录带上当时的方案名（`preset`），用于复盘分组；没有当前方案时为空，显示为「未用方案」。

## 进度看板

- 「进度」分段是职位唯一列表：自动沟通 / 自动投递建档的职位（`source=auto`，带 `platform`，卡片显示「BOSS 自动加入」或「智联 自动加入」）与用户手动添加的职位。自动记录按公司+岗位（去空白、忽略大小写）匹配；没有就新建，带薪资和方案名；职位满 500 条时只记记录不建档。
- 阶段：准备中（旧版草稿/已复制）→ 已沟通（自动沟通/手动添加）→ 已发简历 → 面试 / Offer / 不合适。自动 status 只前进（已发简历不退回已沟通）。面试、Offer、不合适是用户手动标记的 `outcome`，与 status 分开存，自动记录不会覆盖；选「自动阶段」即清除。备注最多 200 字。
- 手动添加只填公司、岗位、备注，用于跟踪用户自己在招聘平台联系或被内推的职位，记为「已沟通 · 本人记录」（`APPLIED_SELF_REPORTED`），是自述、未核验；不进入数据复盘漏斗。用户已确认去掉职位描述、沟通文案、复核复制和「本人已投递」。
- 只有手动职位可「编辑」（改公司、岗位、备注）；自动建档的职位按公司+岗位对应记录，不允许改名，只能标阶段、写备注或删除。删除职位不影响投递记录。
- 0.9.11 及以前保存的草稿保留原有描述、文案和状态字段，可查看、标阶段和删除，编辑时不清除这些字段。

## 数据复盘

- 近 7 / 30 天（含今天，不补未来日期）。漏斗以职位（平台 + jobKey）为单位：区间内自动联系过的职位（BOSS 沟通 + 智联投递，首格叫「联系」）→ 其中已发简历 → 其中手动标为面试或 Offer → 其中 Offer；不合适单列。
- BOSS 的「已发简历」只表示对方回复后自动发出了简历，用作回复的近似；智联投递即附带简历，直接计入。不写“回复率”，不表述为 HR 已读。不读聊天内容。
- 每日沟通柱状图与按方案分组（沟通 · 已发简历）。纯函数 `jobReviewSummary` / `JobReview.summary` 两端同口径。

## 投递记录

- 「数据」分段下方显示最近 30 条（时间 · 公司 · 岗位 · 结果 · 所用简历或失败原因），运行日志可折叠。
- 「清空记录」须确认，并提示清空后去重与今日计数一并重置；运行中不可清空。
- 记录不按时间自动删除：去重（同一职位只沟通一次、只发一次简历）依赖全部历史记录。Android 最多保留 5000 条，超出时丢弃最早的（`AutoApplyRules.addRecord`）；浏览器原型只在内存，刷新即清空。「最近 30 条」是列表显示条数，「近 30 天」是复盘统计窗口，都不删除数据。进度看板职位同样不自动删除，上限 500 条。

## 代码位置

- 纯规则：`domain/AutoApply.kt`（`JobPlatform`，`AutoApplyRules` 匹配/去重/上限，`BossScreenReader` / `ZhaopinScreenReader` 界面识别、`PlatformReader` 按平台分发，`AutoApplyEngine` 沟通状态机、`ResumeEngine` 发简历状态机、`ZhaopinApplyEngine` 智联投递状态机）。改识别规则或流程优先改这里并补 `AutoApplyTest`。
- 平台：`platform/BossUiMap.kt`（节点快照、按路径找回节点、诊断导出，按平台读版本）、`platform/BossAutomationService.kt`（无障碍服务、事件驱动步进、暂停/继续、通知、`BossAutomation` 进程内通道；`start(context, task, platform)`，类名沿用 Boss 前缀，两个平台共用）、`platform/BossOverlay.kt`（悬浮按钮）、`res/xml/boss_automation_service.xml`。
- 数据：Room v6 表 `auto_apply_records`、`auto_apply_settings`，写入统一走 `FocusRepository`；不进入完整备份，`restoreBackup` 原样保留。
- 识别规则来自常见布局猜测，必须用真机诊断导出核对后再调整关键词和 viewId 片段。

## 浏览器原型

- 只用内存演示同样的信息层级（状态卡、准备清单、`role="tablist"` 四段切换、筛选方案、进度看板、数据复盘、我的简历、投递记录与清空、高级），明确标注“原型模拟，不操作任何 App”。真实执行在原型里按步骤间隔逐条写入记录，用于演示状态卡上的暂停/继续/停止；悬浮按钮和亮屏只用文字说明“Android 运行时显示悬浮按钮并保持亮屏”，不模拟悬浮窗。不读写剪贴板、不联网。动态文本用 `textContent`。

## 验证

- 快速：`node --check app.js`、`node --check model.js`、`node --test model.test.cjs`。
- Android 单测：`AutoApplyTest`、`JobAssistTest`；Gradle 与截图按 `rules/verify.md` 交给用户。
- 智联真机顺序：切到「智联招聘」→ 界面诊断（职位列表、详情、已申请详情、简历选择、确认框、投递成功各记录一页）并导出给助手核对包名和识别规则 → 智联试运行 → 智联上限设 1–3 小批量真实投递 → 检查暂停/继续/停止与投递记录 → 切回 BOSS 确认计数不受智联记录影响。
- 真机顺序：开启无障碍 → 界面诊断（职位列表、详情、聊天、消息列表、简历选择框、发送确认框各记录一页）并导出给助手核对识别规则 → 试运行核对清单 → 上限设 1–3 小批量真实执行 → 等 HR 回复后做发简历试运行、再上限 1 份真实发送 → 检查悬浮按钮显示、拖动、暂停/继续/停止，运行中不自动熄屏；分别触碰 BOSS、切走 BOSS、按电源键，确认都只暂停且能继续 → 核对关键词简历与默认简历选择 → 检查投递记录与清空。构建通过不等于自动化可用。
