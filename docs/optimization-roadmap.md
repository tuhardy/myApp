## 1. 全量备份与恢复（进行中：实现完成，待本机验证）

### 目标

现有 JSON 备份不包含日记、草稿、资产、求职记录和音乐文件。新增兼容旧 JSON 的全量备份，使卸载、换机或签名迁移前有可用的数据兜底。

### 范围

- Android 使用带格式版本的 ZIP：数据清单 JSON、日记附件、音乐音频与封面。
- 数据覆盖项目、待办、专注、进度、设置、日记与草稿、资产与心愿、职位与自动投递、曲库元数据；活动计时仍按现有约束先结束或放弃。
- 保留旧 JSON 导入，不把“恢复旧备份时保留未包含数据”的兼容行为改成清空。
- 导出前显示内容范围；恢复前显示格式、记录数量、附件数量/大小及覆盖风险。
- 附件只允许使用经过校验的相对路径或文件名，拒绝路径穿越、绝对路径、重复条目、超限条目和缺失引用。
- 恢复必须先完整校验，再在事务中替换元数据；文件操作失败不得伪报成功，且尽可能保留可恢复的旧数据。
- 浏览器原型同步备份入口的信息层级和流程说明，但不宣称读写真实手机或保存本机持久数据。
- 更新 `rules/diary.md`、`rules/music.md`、`rules/profile.md`、`rules/automation.md` 的备份约定。

### 验收

- 旧 JSON 仍能恢复，旧格式行为有回归测试。
- 全量 ZIP 往返后各模块记录一致，附件可读取且哈希一致。
- 缺文件、重复文件、非法路径、损坏 ZIP、格式版本不支持时均失败且不覆盖现有数据。
- 恢复时清理不再引用的附件，不能误删仍被日记、草稿或曲库引用的文件。
- 快速检查通过；Android 构建、单测、lint 和真机导出/恢复由用户执行并单独记录。

## 2. Android CI 与集成测试（待开始）

- 新增 Android GitHub Actions：相关文件变化及 PR 时运行单元测试、lint 和 debug 构建。
- 优先补 `FocusRepository` 持久化/恢复、计时重建、音乐导入失败清理、日记附件保护测试。

验收：CI 能阻止测试、lint 或构建失败合入；关键数据路径有失败场景测试。

## 3. 计时渲染与重组优化（待开始）

- Android 将 `nowElapsed` 下沉到实际显示组件，缓存求职汇总和 `pendingProgress` 等派生结果。
- 页面只订阅需要的状态；计时检查点的恢复语义先保持不变，测量后再考虑频率。
- `BossAutomation.tryReEnable` 移出 Compose 组合阶段。
- 浏览器仅在运行且需要显示时刷新计时 DOM，隐藏/暂停/ idle 时空转不重复写界面；返回前台立即补算。

验收：计时规则测试不退化；可用性能记录或重组计数证明无效刷新减少；两端交互保持一致。

## 4. Release、签名与包体（待开始）

验收：行为不变，双端同口径样例可自动发现漂移，模块边界更清楚。
